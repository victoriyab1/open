# Размещение без банковской карты

Схема: Telegram → Python webhook на Render → PostgreSQL в Neon. cron-job.org каждую минуту обращается к защищённому `/cron`. Скрипт проверяет местное время и выдаёт урок один раз в день в 12:00. Короткое окно допускает задержку до 12:14; пропущенные даты не наверстываются.

Условия проверены 16 ноября 2026 года. Бесплатные планы имеют квоты и могут меняться. Не подключайте карту и не включайте платные планы. Если сервис потребует карту, остановитесь на этом шаге и сообщите об этом — автоматической замены на платный тариф нет.

## 1. Аккаунты

- [GitHub](https://github.com/signup) — репозиторий исходников.
- [Render](https://dashboard.render.com/register) — один Web Service на плане Free.
- [Neon](https://console.neon.tech/) — проект PostgreSQL на плане Free, без ограничения в 30 дней как у бесплатной базы Render.
- [cron-job.org](https://console.cron-job.org/signup) — бесплатное расписание.

Для Render и Neon удобно использовать вход через GitHub. Регистрируйте аккаунты на свою почту и самостоятельно проходите проверки входа.

## 2. База Neon

1. Создайте проект PostgreSQL на плане **Free**.
2. Выберите регион по возможности рядом с Render.
3. Откройте **Connect**, включите pooled connection и скопируйте connection string с `sslmode=require`.
4. Не отправляйте эту строку в переписку: она содержит пароль. Вставьте её скрытым вводом в `configure.py` или в секретную переменную Render `DATABASE_URL`.

На Render нельзя использовать локальный SQLite: файловая система временная, и прогресс пропадёт после перезапуска. Программа запрещает такой запуск при наличии системной переменной `RENDER`.

## 3. Привязка владельца и секреты

Локально установите зависимости по README и выполните:

```bash
.venv/bin/python configure.py
```

Введите токен BotFather в скрытый запрос. Скрипт покажет одноразовую команду — отправьте её **с вашего личного аккаунта** своему боту. Так определяется разрешённый Telegram ID без стороннего бота. Когда скрипт спросит строку Neon, вставьте её; адрес Render можно добавить позже.

Файл `.env` содержит:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен BotFather |
| `OWNER_TELEGRAM_ID` | Только ваш числовой ID, не username |
| `DATABASE_URL` | Строка Neon PostgreSQL с SSL |
| `WEBHOOK_SECRET` | Сгенерированный секрет для запросов Telegram |
| `CRON_SECRET` | Другой сгенерированный секрет для Cron |
| `DEFAULT_TIMEZONE` | Начальный пояс, например `Europe/Moscow` |
| `PUBLIC_URL` | Адрес Render; нужен локальной команде настройки webhook |

`WEBHOOK_SECRET` и `CRON_SECRET` должны совпадать между локальным `.env` и настройками Render. Не создавайте разные значения в этих двух местах.

## 4. Репозиторий GitHub

Создайте репозиторий и загрузите содержимое папки проекта. Можно выбрать **Private** и предоставить Render доступ только к этому репозиторию. Не загружайте `.env`, `.venv`, базы, `.deploy-state.json`, скачанный PDF или кеши. В проекте есть `.gitignore`.

Если на этапе публикации вы пользуетесь архивом проекта, он уже исключает эти файлы. Загружайте распакованное содержимое, а не сам ZIP.

## 5. Render

Создайте **New → Web Service**, подключите репозиторий и задайте:

| Поле | Значение |
| --- | --- |
| Runtime | Python 3 |
| Plan / Instance Type | **Free** |
| Root Directory | пусто, если код в корне репозитория |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn --workers 1 --threads 1 --timeout 120 --bind 0.0.0.0:$PORT wsgi:app` |
| Health Check Path | `/health` |

В **Environment** добавьте значения из `.env`, а также `PYTHON_VERSION=3.12.12`. Если используете `render.yaml`, перенесите сгенерированные секреты в локальный `.env` либо задайте свои одинаковые значения. Если Blueprint требует карту, создавайте Web Service вручную; карту не добавляйте.

Запустите развёртывание. После статуса Live откройте `https://ВАШ-СЕРВИС.onrender.com/health`: ожидается `status: ok`. Первый запуск создаёт таблицу базы автоматически. Проверка `/health` сама не обращается к базе; ошибки подключения базы видны при запуске сервиса, webhook или Cron.

## 6. Подключение Telegram

Добавьте адрес сервиса в локальный `.env`:

```dotenv
PUBLIC_URL=https://ВАШ-СЕРВИС.onrender.com
```

Выполните локально:

```bash
.venv/bin/python manage.py set-webhook
.venv/bin/python manage.py webhook-info
```

Команда задаёт секрет webhook, последовательное получение обновлений и русское/английское меню команд. Ожидается `configured: True`. Отправьте `/start` боту, выберите язык и часовой пояс, пройдите первый урок. Если раньше работал `manage.py poll`, сначала остановите его: polling отключает webhook и не должен работать одновременно с облачным вариантом.

## 7. Расписание Cron

Вариант вручную в cron-job.org:

- URL: `https://ВАШ-СЕРВИС.onrender.com/cron`.
- Метод: **POST**.
- Периодичность: **каждую минуту**, timezone `Etc/UTC`.
- Заголовок: `Authorization`, значение `Bearer ВАШ_CRON_SECRET`.
- Не записывайте секрет в URL или тело запроса.
- Включите уведомления при трёх последовательных ошибках и при автоматическом отключении задания.
- Не сохраняйте ответы без необходимости; в них только статус, без прогресса.

Либо создайте API key в **Settings → API** и выполните:

```bash
.venv/bin/python scripts/configure_cron.py
```

Ключ вводится скрыто и не сохраняется. Повторный запуск обновляет то же задание по локальному файлу `.deploy-state.json`.

Частые обращения проверяют время и позволяют повторять доставку после сетевой ошибки. В спокойном состоянии endpoint использует кеш расписания и **не будит базу каждую минуту**. После изменения языка, пояса или паузы кеш обновляется. Запускайте один worker/thread: несколько процессов могут хранить разные копии кеша.

Обычный Linux Cron тоже поддержан. При постоянно работающем webhook запускайте `manage.py tick` раз в минуту с рабочей директорией проекта. Этот режим проверяет базу при каждом запуске; для выбранного бесплатного Neon предпочтителен HTTP-вход выше.

## 8. Приёмка после публикации

1. `/start`: выбор языка и пояса, три слова и кнопки озвучки.
2. «Начать сопоставление»: перевод, затем пиньинь, ошибки отмечаются, повторные нажатия не меняют результат.
3. После урока `/lesson` открывает только практику. `/stats` показывает три открытых слова.
4. Архивирование исключает слово из новых повторений; `/archive` → «Повторять» возвращает его на завтра.
5. Изменение языка и пояса через `/settings` сохраняется после перезапуска Render.
6. Test run Cron возвращает HTTP 200. Вне полудня нормально видеть `lesson_created: false`.
7. В следующий день в местные 12:00 появляется новая порция; повторная проверка не отправляет её второй раз.
8. Со второго аккаунта бот не отвечает и не создаёт записи пользователя.

До этого этапа реальные Telegram, Neon и расписание нельзя считать проверенными. Автоматические тесты используют подмену Telegram и локальную базу.

## Бесплатные лимиты и обслуживание

- [Render Free](https://render.com/docs/free): 750 часов на workspace в календарный месяц, временный локальный диск, сон после 15 минут простоя. Используйте один сервис. Без платёжного метода при исчерпании включённых ресурсов сервис может быть приостановлен. После простоя/перезапуска возможны задержки, а таймаут cron-job.org составляет 30 секунд. Следующий минутный запрос повторит попытку.
- [Neon Free](https://neon.com/pricing): PostgreSQL без карты, квоты хранения и вычислений. База может засыпать; программа не держит открытых соединений. Не отключайте scale-to-zero и не включайте платные планы.
- [cron-job.org](https://cron-job.org/en/faq/): бесплатные HTTP-запуски, без обещания точности до секунды. При длительных сбоях задание может отключиться — следите за уведомлениями.

Если одновременно недоступны сервер и планировщик всё окно 12:00–12:14, сегодняшний автоматический урок пропускается. `/lesson` остаётся доступен после восстановления. Очередь уже созданных сообщений сохраняется в базе; новые карточки из очереди не отправляются после окончания их календарного дня.

Не реже раза в месяц проверяйте квоты и статус задания. Для резервирования прогресса можно использовать экспорт PostgreSQL из Neon; выгрузки содержат личные данные и не должны попадать в репозиторий.
